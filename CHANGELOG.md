# Changelog

## 0.7.1 (2026-10-21)

- **CuboEmbedding:** public `PCA.project(_:mean:basis:dims:components:centred:into:)`, the Float32 projection of one vector on the principal components (`vDSP_vsub` centring, exact; `vDSP_dotpr` accumulation). It is the code mac4DSTEM's `DiffractionEmbedding.project` ran, and `PCA.fit(variant: .diffractionEmbeddingApp)` now calls it for its scores (same instructions, results unchanged). Tolerance, written in `ProjectFloatTests`: against a Double sum, `dims * 6e-8 * sum|centred * basis|` per coordinate (measured 1.8e-8 relative at 1024 dimensions); centring bit-exact. `tools/consumer-check`: 138 checks.
- Not provided (documented ask): a Metal selected-area (weighted-pattern) kernel and a GPU-resident cube. `VirtualDiffraction.pattern` stays CPU (compensated Double). The app's `VirtualDiffraction.metal`, `FourDArray`, `ResidentCube`, `PendingLoad` and `VirtualDetector.tiledDiffraction` stay in mac4DSTEM until that is sized as its own change.

### Migration

Additive. In mac4DSTEM: `DiffractionEmbedding.project` is deleted; call `PCA.project` (same signature).

## 0.7.0 (2026-10-21)

Parity with the app's copies, so mac4DSTEM can delete its ptychography engine, parallax alignment and the numerics below (the learned detector stays in the app). Timings: release build, one core, Mac under load 5-9, best of 5-20.

- **Speed, no API change (CuboCore `FFTPlan`/`FFT2D`):** the Double transform runs on `vDSP_DFT_zop` for the lengths vDSP takes (2^n x {1, 3, 5, 15}) and keeps the radix-2/Bluestein path for the rest; 5-7x faster than `vDSP_fft_zipD` from 128 x 128. It checks against a naive DFT (1e-12 of the largest coefficient) and against 0.6.0 (CuboPtycho object 1.7e-11, spectrum 2.4e-13, shift 3.3e-15 on a 3-iteration case: no pinned fixture moved). `FFT2D.transform(real:imaginary:inverse:scratch:)` is the allocation-free `package` entry. `ParallaxAlignment.apply` builds the phase from a row and a column ramp, not one `sincos` per pixel.
- **CuboPtycho single-slice engine:** the Fourier-modulus projection is `measured * F / |F|` (no `atan2`/`cos`/`sin`), shift ramps are separable, no per-pattern allocation, pointer loops: 3 iterations of 100 patterns at 64 x 64 take about 30 ms in Double (0.6.0: 60 ms). New `precision: .single` (and `SingleslicePtychography.reconstructSingle(amplitudes: [Float], ...)`): Float32 on vDSP's DFT, about 14 ms (the app's engine: 15 ms). Float32 tolerance, written in `SinglePrecisionTests`: object 1e-4 absolute on a unit-modulus object (measured 2.9e-5; non-square detector with fractional positions as well), probe 1e-5 (measured 1.5e-6), error history 1e-4 relative. The Float path needs a detector size vDSP takes and has no position correction (both throw `invalidInput`). `isCancelled:` and `progress:` on `reconstruct`.
- **CuboParallax:** `ParallaxFourierShifter.shiftedSingle` (image and batch, with `isCancelled:`/`progress:`) and `supportsSingle`: 0.19 ms per 160 x 160 shift against 0.47 ms Double (0.6.0: 1.28 ms; the app: 0.22 ms); agrees with Double to 1e-5 of the image range. `ParallaxPreprocessing.prepare(source:...)`: streamed, two passes over scan-row tiles of any `CubeSource`, flat Float stacks `[bright-field pixel][row][column]`, mask, probe angles in mrad, `maximumStackBytes` refusal (`ParallaxError.stackTooLarge`), progress, `isCancelled`; matches the resident `prepare` to 2e-5 relative (measured 3.9e-7) and is exact across tile sizes.
- **CuboVirtual:** `OriginEstimator` (`.py4DSTEM`, `.iteratedWindow(passes:minimumMargin:binnedCoarse:)` = the app's estimator) with `OriginMeasurement.measure(of:radius:radiusScale:estimator:path:...)` on CPU and Metal (`cubo_measure_origin`, Metal against CPU 1e-5) and `OriginMeasurement.windowSensitivity`. Not provided: a Metal weighted-pattern kernel (`VirtualDiffraction.pattern` sums in compensated Double).
- **CuboStrain:** public `LatticeStrain.fitRobust`, `scoreBasis`, `indexingTolerance`, `conditionNumber`, `indexByRounding`, `StrainFrame.rotate`; `StrainFitMethod.robustIntensityOnce`; `StrainMapOptions.indexing` (`.nearestDirection` default, `.basisRounding`) and `indexingTolerance`; `StrainMapResult.refusedFitCount`, `firstRefusal`, `basisSupportFraction`, `basisConditionNumber`. Double helpers agree with the app's Float formulas to 1e-6 (tests 1e-9 against a Double transcription).
- **CuboBragg:** `BraggDisks.detectAll(in:kernel:options:tiling:failurePolicy:isCancelled:progress:)` returning `BraggScanResult` (`vectors`, `failedPositions`, `firstFailure`), `BraggFailurePolicy` (`.throwOnFirst`, `.recordEmpty`), `BraggDiskOptions.validate()`. The old `detectAll` is unchanged in behaviour. `FloatFFT2D` moved to CuboCore (`package`).
- **CuboCore:** `HotPixelFilter.replacing(in:base:plan:validatingFinite:)`, the in-place loop entry on a `Replacer` (checks only the pixels the plan reads); bit-identical to `replacing`.
- `tools/consumer-check`: 137 checks. No new negative controls (`controls.sh` not extended this release).
- Package.swift has no sibling-kit dependencies, so no ranges were widened.

### Migration

Additive, with two edges: `ParallaxError` gains `stackTooLarge` (an exhaustive `switch` needs a default), and the Double FFT results move by about 1e-15 relative. In mac4DSTEM: `SingleslicePtychography.reconstruct(precision: .single, isCancelled:, progress:)` replaces the app's engine (no position correction there, as in the app); `ParallaxFourierShifter.shiftedSingle` and `correlationShift` replace `ParallaxAlignment`'s Float path, with `MatrixDFTCorrelation` going through `ParallaxAlignment.shift` (Double, about 4 ms per peak); `ParallaxPreprocessing.prepare(source:)` replaces `ParallaxPreprocessor.run` (kit angles are mrad; sampling per axis); `OriginMeasurement.measure(estimator: .iteratedWindow, path: .metal)` replaces `MetalEngine.measureOrigins`; `BraggDisks.detectAll(failurePolicy: .recordEmpty)` replaces `DiskDetection.detectAll`; `LatticeStrain.fitRobust` and `StrainMapOptions.indexing: .basisRounding` replace `StrainMapping`'s fit and indexing. Stays in the app: the learned detector (training, refine), display Metal, `ParallaxPhysicalCalibration`, `PhaseContrastMemoryBudget`, the `condition <= 8` refusal of a given basis (use `LatticeStrain.conditionNumber`).

## 0.6.0 (2026-10-21)

The app's remaining kit asks, so mac4DSTEM can drop its copies. Every addition is opt-in or additive; defaults keep 0.5.0 results (CuboParallax's default position correction now throws instead of trapping on a flat score map, below). Tolerances are written in each test and measured against py4DSTEM 0.14.19 (`f050d207`), scikit-learn 1.4.2 or a transcription of the app source.

- **CuboBragg, single precision:** `BraggDiskOptions.precision` (`BraggPrecision.single`) runs the pattern copy, filters, 2-D FFT, correlation and maxima search in Float32 (vDSP) with per-worker scratch; accepted peaks are refined in Double. Sizes vDSP's DFT does not support (f·2^n, f in 1, 3, 5, 15) throw `invalidOption`; `BraggDetector.supportsSinglePrecision` asks. 256 x 256, poly: 0.47 ms serial / 0.14 ms wall on 18 cores against 5.31 / 0.87 for `.double`; the app's own detector measured 0.24-0.27 ms wall. Pins: positions 1.3e-5 px (tolerance 5e-5), intensities 1.1e-6 (5e-6). `correlationPower` near 0 is not held in Float32 (documented). Also `BraggFunnel` and `detectWithFunnel` (per-stage counts as the app reports them, peaks identical to `detect`), `BraggMaxima.findWithFunnel`, public `BraggDetector.fillNonFinite` (Double and Float) and Float-buffer `detect`.
- **CuboPtycho:** `constrainObjectAmplitude` on the single-slice engine (off skips the |object| <= 1 cap; DEVIATION, pinned to py4DSTEM with only that constraint replaced, gap 1.8e-7 at 2e-6); `PtychographyAberrationTerm` (any radial/angular order, cosine or sine, `.polar` for py4DSTEM's C_nm, phi_nm) as `higherOrder:` on `PtychographyProbe.build`, `PtychographyPreparation.initialProbe` and `PtychographyPreparationOptions.higherOrderAberrations` (C21 to C56 pinned to py4DSTEM at 1.2e-7; orders py4DSTEM cannot express to a NumPy transcription of the app, 4.8e-10).
- **CuboParallax:** `ParallaxFourierShifter` (plan built once, batch shifts, bit-identical to `ParallaxAlignment.shifted`); `ParallaxAlignment.correlationShift` on `ParallaxSpectrum` (the app's spectrum-level estimate, 3.3e-14 px); `ParallaxCorrectionResult.transferReal/transferImaginary`; `isCancelled:` and `progress:` on alignment, batch shift, `reconstruct`, `process`, `section` and `correctPositions` (`CancellationError`); `ParallaxDepthSectioner` (forward FFTs once, `plane(atDepth:)`; `section` planes bit-identical); `ParallaxPositionCorrectionVariant.application` (the app's Float loop, offsets exact, image 5.5e-8). Behaviour change: the default position-correction loop on an exactly flat score map used to trap on NaN coordinates and now throws `ParallaxError.nonfiniteValues`.
- **CuboEmbedding:** `PCACovarianceAccumulator` (streamed, mergeable, Chan/Welford in Double), `PCA.fit(covariance:count:mean:components:)` and `PCASignResolver` (svd_flip signs in a second pass; streamed fit equals scikit-learn to 2e-12 on components, 1e-15 on variance, invariant to tile order); `DiffractionFeatures.binnedVector(implementation: .accelerate)` (the app's vDSP path, 2.7e-7 relative to the scalar one; non-finite patterns fall back to scalar; default `.scalar`); `isCancelled:` on `KMeans.fit` and `fitSeeded`.
- **CuboStrain:** `LatticeStrain.chooseBasisConsensusResult` (`ConsensusBasis`: basis, observation and support counts, residual, condition number, indexing tolerance; `isCancelled:`), `referenceMADResult` (`ReferenceMAD`: reference and inlier indices), `StrainMapResult.referenceInlierCount`. The plain calls return identical bases.
- **CuboCore:** `HotPixelFilter.Replacer`, the mask's clipped neighbour lists built once; `apply` replaces in place with no allocation, 0.005 ms against 0.054 ms per 256 x 256 pattern with 40 masked pixels, bit-identical to `replacing`, which keeps its validate-and-copy contract (and its time).
- `tools/consumer-check`: 105+ checks and the new controls for every new public symbol; CuboParallax is covered for the first time.

Additive. In mac4DSTEM: `DiskDetector` can call `BraggDetector` with `.single` (and `detectWithFunnel`, `fillNonFinite`); the ptychography settings map onto `constrainObjectAmplitude` and `PtychographyAberrationTerm` (cartesian C12 to polar: `C12 = hypot(a, b)`, `phi12 = atan2(b, a) / 2`); parallax drops its Fourier shift, correlation estimate, transfer-function recomputation and per-plane re-FFT for the shifter, spectrum estimate, transfer fields and sectioner; embedding drops `BinGeometry`, the `embed` fast path and the covariance eigen shim; strain drops the re-scoring in `estimateLatticeBasis` and `robustReferenceIndices`; `CalibratedDataCubeWriter` can reuse one `HotPixelFilter.Replacer`. ## 0.5.0 (2026-10-20)

App-resident computation moves into the kit, each piece pinned to py4DSTEM 0.14.19 (`f050d207`), NumPy or a transcription of
the app source, with the tolerance written in its test (`docs/ptycho.md` has the measured gaps).

- **CuboPtycho preprocessing:** `PtychographyPreparation` (`amplitudes`, `scanPositions`, `objectShape`, `centerPositions`, `initialProbe`, `prepare`) builds the amplitude stack, scan positions, object canvas and starting probe from a `CubeSource`. Bilinear and cubic-spline (SciPy grid-wrap) pattern shifts, py4DSTEM's rotation/transpose/padding, Float32 rotation matrix reproduced. Measured gaps 4.2e-8 (amplitudes), 0 (positions), 6e-8 (probe) at tolerance 2e-6. The app's choices are named options (`PtychographyPreparationOptions.mac4DSTEM`: bilinear shifts, per-axis padding, no re-centring, clipped mean intensity).
- **CuboPtycho engines:** `MixedstatePtychography` (`reconstruct`, `orthogonalize`, `initialProbes` with NumPy-compatible seeded states) and `MultislicePtychography` (`reconstruct`, `propagators`, `identicalSlices`), CPU Double beside `SingleslicePtychography`; new `PtychographyStack` type. Measured gaps 3.9e-7 at 2e-6 over 11 py4DSTEM cases; one slice equals the single-slice engine to 2e-16.
- **CuboPtycho constraints:** `fixProbeAperture` and `probeSupportMask` on all three engines (off by default), pinned to py4DSTEM on each.
- **CuboCore:** `ViewedCube`, `CubeViewSpecification`, `CubeViewGeometry`, `AxisCrop`: scan crop, detector crop and detector bin applied at read time to any `CubeSource` (py4DSTEM `crop_data_real`, `crop_data_diffraction`, `bin_data_diffraction`: crop first, remainder trimmed off the end, blocks summed). Shapes and integer sums exact, float sums within 1e-6 (measured 1.2e-7). `AxisCrop.enclosing` is the app's drag-rectangle arithmetic. New error case `CuboError.invalidView`.
- **CuboPhase:** `DPCViews` (magnitude, angle in [0, 2 pi) with py4DSTEM's `row + i column` direction or the image-frame `atan2(row, column)`, milliradians per pixel) and `RotationConvention` (the sign flip between py4DSTEM's R-Q angle and an image-frame caller's, display text), NumPy-pinned.
- **CuboPtycho error normalisation:** the engines take `errorNormalization` (`.meanIntensity(m)`: py4DSTEM's residual over `m * positions`, with `PtychographyAmplitudes.errorNormalization` giving it for preprocessed amplitudes; `.suppliedAmplitudeEnergy`: the previous behaviour, still the default because bare amplitudes carry no mean) and the mixed-state engine `zeroFarFieldPixelError` (`.reference`, the default: py4DSTEM's infinite term for an exactly zero far-field pixel; `.finite`: the previous `measured^2`). The pins now go through py4DSTEM's preprocessing with a mean that differs from the amplitude energy by more than 2 percent; the old normalisation fails them.
- **CuboPtycho position correction:** `SingleslicePtychography.reconstruct(positionCorrection:)` (`PtychographyPositionCorrection`: step size, maximum update and total distances in Å, centre-of-mass constraint) and `Result.positions`; five py4DSTEM cases, positions 6.2e-7 px, others 4e-7 at 2e-6, plus an exact-data sign check. Off by default.
- **CuboPtycho odd sizes:** preprocessing and the three engines pinned on odd, non-square detectors, probes and objects (`odd.json`); no defect found.
- **CuboCore:** `OriginFit.fitTrimmed` (`TrimmedOriginFit`), the MAD-trimmed origin fit of the app's calibration, beside `OriginFit.fit`: joint residual, `median + 3 * 1.4826 * MAD`, up to three rounds, final fit on the kept mask; fourteen cases pinned to a Float32 transcription of the app source (mask exact, surfaces 6e-8) and to py4DSTEM's masked `fit_origin` (1.3e-8). `AxisCrop.rowRange`, `columnRange` and `fits` saturate or refuse instead of trapping on extreme integers, and `AxisCrop.enclosing` returns `nil` when a stride product overflows.
- `docs/parity.md`: 79 done, 37 partial, 66 absent of 182 (crop_Q, crop_R, bin_Q done; mixed-state and multislice partial).

### Migration

Source-compatible except that `CuboError` gains a case (`invalidView`): an exhaustive `switch` over it needs a default, and `SingleslicePtychography.Result` gains `positions`. `SingleslicePtychography.reconstruct` gains defaulted parameters (`fixProbeAperture`, `probeSupportMask`, `errorNormalization`, `positionCorrection`); the other engines gain `errorNormalization`, and the mixed-state one `zeroFarFieldPixelError`. Behaviour change: with a mixed-state engine, an exactly zero far-field pixel now makes the iteration's `error` infinite (py4DSTEM); pass `zeroFarFieldPixelError: .finite` for the old value. A caller that wants py4DSTEM's `errors` passes `errorNormalization: amplitudes.errorNormalization`. A caller in the app moves: the preparer (`PtychographyPreparer`) to `PtychographyPreparation.prepare(..., options: .mac4DSTEM(...))` after relabelling its axes to py4DSTEM's (its x and y are the kit's column and row); the load view's crop and bin to `ViewedCube` (its bin factors 2, 4, 8 stay the app's policy); the DPC magnitude and angle images to `DPCViews` (Double, not Float32 interleaved) and the rotation sign to `RotationConvention`. Not moved: the colour wheel (a display), the byte-count and residency arithmetic of the load configuration, the UI selection state.

## 0.4.0 (2026-10-20)

Three additions, each pinned to py4DSTEM 0.14.19 (`f050d207`) with the tolerance written in its test.

- **CuboPtycho:** `SingleslicePtychography.reconstruct` gains `fixProbeCenterOfMass`, `constrainProbeAmplitude`, `probeAmplitudeRelativeRadius` (0.5) and `probeAmplitudeRelativeWidth` (0.05), all off by default so every earlier result is unchanged (py4DSTEM turns the centre-of-mass constraint on by default; here it is the caller's choice). Four new py4DSTEM cases, measured gap 3.6e-7, tolerance 2e-6. Radius outside 0...0.5 or width outside (0, 0.5] is `invalidInput`. Other probe constraints (aperture, Fourier amplitude, aberration fitting, support) remain absent.
- **CuboParallax:** `ParallaxReconstruction.reconstruct` ports `Parallax.reconstruct` (alignment-bin schedule, running reference, Bernstein regularisation, median centring, per-bin error), and `ParallaxReconstruction.process` runs prepare, reconstruct and the optional KDE upsampling and position correction in one call. Seven py4DSTEM cases, gaps 1e-7 to 9e-7 (tolerance 5e-6 on shifts, 2e-6 on images). Named option `emptySchedule = .singlePassAtMinimumBin` is the app's behaviour where py4DSTEM raises. Aberration fit and correction and depth sectioning stay separate calls. Not provided: initial aberration shifts, real-space mask, continue/reset, batching.
- **CuboStrain:** `StrainMapping` (`histogram`, `chooseBasisVectors`, `compute`, `centredPeaks`) is the scan-level pipeline of py4DSTEM's `StrainMap`: Bragg-vector histogram, basis choice, per-position fits, reference, strain maps with coordinate rotation. Pinned to six `StrainMap` runs and five histograms (strain gap 1.8e-15, tolerance 1e-9). `LatticeStrain.chooseBasis` gains an overload with explicit `indexOrigin/G1/G2`. `BraggDiskOptions.tieOrder` (`.rasterOrder` default, `.numpy` for py4DSTEM's order of equal maxima) is new in CuboBragg. `tools/consumer-check` scope checks, which tested a string that no longer existed, now test real scope text.
- `ParallaxPreprocessingResult` gains `scanRows`, `scanColumns`, `paddedWindow` (`correctPositions(window:)` takes `paddedWindow`, as its comment now says).
- `docs/parity.md`: 76 done, 35 partial, 71 absent of 182.

### Migration

Additive for the source. `CuboStrain` now depends on `CuboBragg` (and through it `CuboVirtual` and `CuboParallax`), so a package that imports only `CuboStrain` builds those too; `StrainDirections.maxima` uses `BraggPeak`, so callers of the maxima path also `import CuboBragg`. `ParallaxPreprocessingResult` has new public fields (its initialiser is internal). Everything else keeps its default.

## 0.3.0 (2026-10-16)

0.3.0 adds seven pieces on the CPU, each pinned, with the tolerance stated in its test, to py4DSTEM 0.14.19 (`f050d207`),
scikit-learn 1.4.2 or a transcription of the mac4DSTEM source (Double, except hot pixels and origin re-referencing in Float32): `CuboParallax` (alignment, preprocessing, aberration fit and
correction, depth sectioning, subpixel upsampling), `CuboPtycho`, `CuboStrain`, `CuboBragg`, `CuboEmbedding`, Fourier
iDPC in `CuboPhase`, and hot-pixel filtering and origin re-referencing in `CuboCore`. Where the mac4DSTEM source differs
from the reference, the difference is a named option and the reference is the default. `docs/parity.md` now counts 73

### CuboParallax

- Add the CPU-only `CuboParallax` product: Double-precision matrix-DFT correlation refinement, periodic Fourier translation, and fixed/running-reference stack alignment (default upsampling factor 8). Public inputs and results are Sendable and independent of app types. Four small stacks pin shifts, shifted images, means and DFT patches to py4DSTEM 0.14.19 (`f050d207`), with `1e-10` normwise tolerance.

- Add CuboParallax constant-order bright-field preprocessing: detector selection, reciprocal vectors, radian probe angles, sine-squared blending and centered padding. Default windowed stack retention follows py4DSTEM; `.unwindowed` retains the app KDE input.

- Add CuboParallax aberration fitting (`ParallaxAberrationFitter`: polar-decomposition low order C1/C12/rotation, higher-order global/recursive fits) and CTF phase correction (`ParallaxAberrationCorrection`). Pinned to py4DSTEM 0.14.19 `aberration_fit`/`aberration_correct` (fit coefficients to 2e-4, relative with a unit floor (absolute below 1), measured 6e-7, against a Float32 reference basis, low order and rotation to 1e-10, corrected image to 2e-6). The reference ignores `q_highpass`; the app applies it, so `.reference` is the default and `.apply` is the app option, with `.detectorGrid`/`.selectedCentroid` basis conventions, the app pinned to a NumPy transcription of the app source.

- Add CuboParallax depth sectioning (`ParallaxDepthSectioning`), py4DSTEM `depth_section` semantics. The reference path (defocus-only sign CTF, optional information-limit envelope) is pinned to py4DSTEM 0.14.19 at 2e-7 measured (tolerance 1e-5 of the maximum over all planes, complex64 reference); py4DSTEM's `use_CTF_fit=True` raises a TypeError at that version, so the full-fit CTF (`.fullFit`, the app's behaviour) is pinned to a NumPy transcription of the app source.

- Add CuboParallax subpixel kernel-density upsampling (`ParallaxSubpixel`): the upsample-factor heuristic and bilinear/Lanczos deposition with Gaussian blur and optional sinc low-pass, pinned to py4DSTEM 0.14.19 `subpixel_alignment` (measured gap 4e-7, tolerance 1e-4; the reference accumulates in Float32). The app's KDE source (mac4DSTEM c809679c) was read against the reference and uses the same formulas, including the Lanczos second-axis window quirk, so there is no separate app option; this was a reading, not a pinned comparison. Probe-position correction (`correctPositions`: gradient and checkerboard steps, Gaussian and Butterworth regularisation) is pinned to the reference over three 3-iteration cases (offset gap 1.7e-5, image gap 6e-7, tolerance 1e-4). The app's variant (no regularisation; clamps the step floor only on rejected sites; guards a zero gradient) is not ported as an option.

### CuboPtycho

- Add CuboPtycho CPU probe construction (defocus, two-fold astigmatism, C30) and full-batch single-slice complex-object gradient descent from preprocessed amplitudes, with fixed positions, optional probe updates and pure-phase object constraints. Pinned py4DSTEM 0.14.19 fixtures cover probe pixels and object/probe after three iterations.

### CuboStrain

- Add CuboStrain basis selection from histogram maxima, measured-direction indexing, intensity-squared lattice fits, median references and rotated infinitesimal strain. Separate intensity-once, MAD-reference and cluster-consensus compatibility APIs preserve the original source numerics. Small binary fixtures pin both conventions.

### CuboBragg

- Add the CPU `CuboBragg` product: py4DSTEM's `find_Bragg_disks` for one pattern, a stack or a cube in Double (hybrid cross-correlation with a `ProbeKernel`, `get_maxima_2D` with its filter cascade, parabolic and multicorr subpixel refinement), plus the app's `ProbeRingHint`. Defaults are py4DSTEM's; the mac4DSTEM differences are named options (`relativeReferenceMinimumRadius`, `nonFinitePixels`, `multicorrOrder`, `BraggDiskOptions.mac4DSTEM`, `detectorAdapted`). Thirty py4DSTEM 0.14.19 cases pin positions and intensities to 1e-9 px / 1e-10 (measured 1.5e-12 / 1.3e-13); ten cases pin the options to the unchanged app source in Float32 (1e-3 px / 1e-5; measured 1.8e-4 / 1.2e-6). `GaussianFilter.apply` gains an `edge:` parameter (`.reflect`, scipy's default); the default `.nearest` is unchanged. `CuboParallax` exposes its matrix-DFT refinement to the package (`package`, no public change).

### CuboEmbedding

- Add CuboEmbedding: `PCA` (scikit-learn 1.4.2 `svd_flip` sign convention, covariance divisor rows - 1) and `KMeans` (scikit-learn Lloyd from caller-given centroids), pinned to scikit-learn. mac4DSTEM's Float32 covariance PCA, seeded k-means and binned diffraction feature vector are separate named options pinned to its original source. Binary fixtures under 50 KB; see `docs/embedding.md`.

### CuboPhase and CuboCore

- Add CPU Fourier iDPC integration in CuboPhase, with periodic or centered zero-padded boundaries, explicit regularization, anisotropic sampling and projected-phase calibration. Regression pins use a NumPy float64 transcription of the app Fourier integration; this is separate from the existing py4DSTEM iterative DPC.

- Add CuboCore hot-pixel filtering, wrapped 21-pixel classification and sequential clipped-window median replacement. Float32 mean accumulation matches py4DSTEM, including the contiguous pairwise reduction for a 1×1 detector. Eight small fixtures pin means, masks and all filtered pixels bit for bit to py4DSTEM 0.14.19.

- Add CuboCore `FrameTransform`: detector-position, scan-crop and per-position origin-map re-referencing under crop and bin, with the pixel-centre bin rule `(v+0.5)/bin-0.5`. py4DSTEM moves no origin on crop or bin (it only multiplies the Q pixel size by the bin factor), so these rules are the app's, pinned Float32 bit for bit to a transcription of mac4DSTEM `CalibrationReReference.swift` at c809679c (`tools/rereference/pins.py`). Calibration objects, provenance and invalidation messages stay in the app.

### Migration

Additive: every 0.2.0 product and API is unchanged, and the new modules (`CuboParallax`, `CuboStrain`, `CuboBragg`,
`CuboPtycho`, `CuboEmbedding`) are new library products a consumer adds only if it wants them. One public signature
gains a defaulted parameter: `GaussianFilter.apply` takes `edge:` (default `.nearest`, as before). `CuboParallax`'s
matrix-DFT refinement is shared with `CuboBragg` through `package` access (no public change). Nothing a consumer
calls moves. Full parallax reconstruction (grouping, schedules, regularisation) is not yet provided.
